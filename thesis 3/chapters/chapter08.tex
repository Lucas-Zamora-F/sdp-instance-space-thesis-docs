\chapter{Conclusiones}
\label{ch:conclu}

Este trabajo abordó la construcción de un pipeline computacional para caracterizar
instancias de programación semidefinida mediante \acrshort{isa}, comparar el
comportamiento de solvers representativos y preparar la generación dirigida de nuevas
instancias sintéticas.
Al cierre de Tesis~3, el resultado principal es una infraestructura integrada que
conecta recopilación de instancias, normalización al formato SDPA sparse, ejecución de
solvers, extracción de features, generación de metadata, construcción del espacio de
instancias y exploración visual de resultados.

La hipótesis inicial planteaba que las instancias de \acrshort{sdp} no se distribuyen
uniformemente en el espacio definido por sus features, y que dicha distribución puede
relacionarse con diferencias de rendimiento entre solvers.
Los resultados parciales obtenidos no constituyen aún una validación final de la
hipótesis, pero sí entregan evidencia inicial a su favor: el espacio construido muestra
una proyección interpretable de las instancias, permite generar footprints de
desempeño y revela regiones con baja densidad que pueden ser usadas como objetivos
para la generación evolutiva.

\section{Cumplimiento de objetivos}
\label{sec:conclusiones_objetivos}

Respecto del primer objetivo específico, se diseñó e implementó un conjunto de
features computables directamente desde instancias \acrshort{sdp} en formato SDPA
sparse.
Estas features capturan propiedades de tamaño, estructura de bloques, dispersión,
conectividad, chordalidad y relaciones algebraicas entre restricciones.
La implementación modular permite calcularlas sin resolver la instancia, preservando
la independencia entre la caracterización estructural del problema y el rendimiento de
los solvers.

Respecto del segundo objetivo específico, se integró el framework \acrshort{isa} al
pipeline experimental.
La metadata generada a partir de features y benchmarking puede ser consumida por
\texttt{buildIS}, produciendo coordenadas, modelo, footprints, portfolios y archivos
auxiliares.
Además, \texttt{exploreIS} permite proyectar nuevas instancias sobre el modelo
construido, habilitando comparaciones entre el espacio original y conjuntos de prueba.
Con esto, la etapa de análisis de espacio de instancias queda operativa para estudios
posteriores de desempeño.

Respecto del tercer objetivo específico, se avanzó en la base necesaria para la
generación evolutiva de instancias.
La aplicación ya permite identificar puntos candidatos en regiones vacías del espacio,
y se dispone de una implementación funcional previa del algoritmo genético que opera
sobre instancias SDPA sparse, aplica operadores evolutivos, evalúa candidatos mediante
features y orienta la búsqueda hacia coordenadas objetivo.
La integración completa de esta implementación con el pipeline actual queda como el
siguiente paso experimental.

\section{Contribuciones principales}
\label{sec:conclusiones_contribuciones}

La primera contribución del trabajo es la consolidación de un pipeline reproducible
para estudiar instancias \acrshort{sdp} desde una perspectiva empírica.
El pipeline permite pasar desde colecciones heterogéneas de benchmarks hasta una
metadata estructurada compatible con \acrshort{isa}, evitando depender de procesos
manuales o formatos intermedios no controlados.

La segunda contribución es la integración de solvers heterogéneos bajo una interfaz
uniforme de benchmarking.
Los runners abstraen diferencias entre ejecutables externos y toolboxes MATLAB,
capturando sus resultados en un formato común.
Esto permite comparar tiempos de \acrshort{cpu}, estados y valores reportados sin que
la heterogeneidad de implementación impida el análisis conjunto.

La tercera contribución es la implementación de un conjunto de features estructurales
para \acrshort{sdp}.
Estas características permiten describir las instancias a partir de su formulación
matricial, su estructura de bloques, su dispersión y sus grafos asociados.
Al calcularse directamente desde el archivo \texttt{.dat-s}, pueden aplicarse tanto a
instancias recopiladas como a instancias sintéticas generadas posteriormente.

La cuarta contribución es la incorporación de una aplicación visual para inspeccionar
los resultados del espacio de instancias.
La interfaz permite explorar proyecciones, identificar puntos, comparar espacios,
cargar metadata de prueba y ubicar regiones vacías.
Este componente es importante porque transforma los resultados de \acrshort{isa} en
objetos explorables, facilitando la interpretación de resultados por parte del
investigador.

La quinta contribución es la conexión metodológica entre \acrshort{isa} y generación
evolutiva para SDP.
El trabajo no se limita a describir el espacio construido: también prepara el uso de
regiones vacías como objetivos para generar nuevas instancias.
Esto abre la posibilidad de ampliar activamente la cobertura experimental del dominio
\acrshort{sdp}.

\section{Limitaciones}
\label{sec:conclusiones_limitaciones}

La principal limitación al cierre de Tesis~3 es que los resultados obtenidos son
parciales.
La infraestructura está implementada y funcional, pero aún falta ejecutar una campaña
experimental completa sobre todas las instancias y todas las features consideradas en
el diseño.
Por ello, las footprints y regiones observadas deben entenderse como validación del
pipeline, no como conclusiones definitivas sobre el rendimiento global de cada solver.

Una segunda limitación es el costo computacional del benchmarking.
Los solvers \acrshort{sdp}, especialmente aquellos basados en métodos de punto
interior o ejecutados dentro de MATLAB, pueden requerir tiempos significativos en
instancias grandes.
Esto obliga a definir límites de tiempo, registrar fallas de convergencia y aceptar
que algunas instancias no produzcan resultados completos para todos los algoritmos.

Una tercera limitación es la integración pendiente del algoritmo genético con la
versión actual del pipeline.
Aunque existe una implementación funcional previa y ya se identifican puntos objetivo
en regiones vacías, todavía falta validar cuantitativamente las instancias generadas:
su distancia final al objetivo, su validez estructural, su diversidad y su efecto real
sobre la cobertura del espacio.

\section{Trabajo futuro}
\label{sec:conclusiones_trabajo_futuro}

El primer trabajo futuro es ejecutar el pipeline completo sobre el conjunto final de
instancias recopiladas.
Esto incluye recalcular todas las features seleccionadas, completar las corridas de
benchmarking, regenerar la metadata final y reconstruir el espacio de instancias con
\texttt{buildIS}.
Con estos resultados será posible analizar de manera más robusta las regiones de buen
desempeño de cada solver.

El segundo trabajo futuro es profundizar el análisis de footprints.
Una vez construido el espacio final, se deberán estudiar las regiones asociadas a cada
solver, las features que explican dichas regiones y los casos donde ningún algoritmo
presenta buen desempeño.
Este análisis permitirá convertir la visualización del espacio en conocimiento
operacional sobre selección de solvers.

El tercer trabajo futuro es integrar completamente el algoritmo genético al pipeline
actual.
Las coordenadas candidatas detectadas en regiones vacías deben alimentar ejecuciones
evolutivas que generen nuevas instancias \texttt{.dat-s}.
Luego, estas instancias deben pasar por el mismo flujo que las instancias originales:
validación, extracción de features, benchmarking, metadata, \texttt{exploreIS} y
comparación visual.

El cuarto trabajo futuro es evaluar cuantitativamente el aporte de las instancias
sintéticas.
Para ello se deben medir indicadores como distancia inicial y final al objetivo,
número de generaciones requeridas, porcentaje de instancias válidas, diversidad de la
población, cambio en la cobertura del espacio y variación en las footprints de los
solvers.
Estas métricas permitirán determinar si la generación evolutiva realmente enriquece el
espacio experimental.


\section{Cierre}
\label{sec:conclusiones_cierre}

En síntesis, Tesis~3 deja establecido un pipeline funcional para estudiar instancias
\acrshort{sdp} mediante \acrshort{isa}.
El trabajo realizado demuestra que es posible unificar instancias heterogéneas,
extraer features, ejecutar solvers bajo una interfaz común, construir un
espacio de instancias y usar dicho espacio para identificar regiones de interés.

Aunque la validación experimental completa queda para la siguiente etapa, la
infraestructura desarrollada reduce significativamente la distancia entre el diseño
metodológico y el análisis final.
El proyecto queda preparado para pasar desde la construcción del pipeline hacia la
interpretación cuantitativa de resultados y la generación dirigida de nuevas
instancias sintéticas.
